# AI-Native Safety Architecture

Status: PROPOSED architecture for prototype validation.

The design assumes the model can be wrong, stale, over-broad, retried, prompt-injected or concurrently operating with another model. Safety therefore lives below model reasoning.

## 1. Application-owned Session Handle

MCP 2026-07-28 is stateless at protocol level. Optic creates an explicit opaque SessionHandle for stateful developer work. It is high-entropy, short-lived, revocable and bound server-side to principal + project grant + policy epoch. Possession alone is insufficient: every call revalidates ownership/scope.

Do not equate a ChatGPT conversation, HTTP connection or MCP transport session with an authorization session.

## 2. Task Lease

A Session can create narrowly scoped TaskLeases: objective label, workspace/worktree, allowed action families, resource budget, expiry and base revision. This lets two chats split work without receiving broad permanent access.

The model can request a lease. Policy/user configuration grants it.

## 3. Action Envelope

Every mutating or process action is normalized into an internal envelope before authorization:

- action_id / session / task;
- typed action;
- canonical target;
- expected state/hash/base revision;
- capability lease;
- resource/output/network budget;
- reversibility class;
- risk/sink class;
- policy epoch.

Adapters cannot bypass this envelope.

## 4. Read-version-write protocol

Reads return content plus a version token/hash. Writes/patches carry the expected token. If another session changed the target, the bridge returns StaleBase/Conflict and the AI must re-read/reason.

This turns stale model context into a detectable concurrency condition instead of silent corruption.

## 5. Source/Sink Firewall

The bridge cannot reliably determine whether arbitrary text contains a successful prompt injection. It therefore constrains impact.

Sources such as repository text, logs and network content are untrusted. Sensitive sinks such as network egress, credentials, policy mutation, external writes and privilege changes are deterministically gated. No “the model says this is safe” bypass exists.

## 6. TransportGuard

Protocol parsing is preceded/followed by hard resource limits owned by Optic: maximum frame/body size, schema depth/validation budget, request concurrency, per-principal rate/budget, response size and cancellation timeout.

This remains required even if RMCP adds equivalent protections. Dependency defaults are not security invariants.

## 7. Risk budget, not risk score

Avoid a probabilistic AI-generated safety score. Use a deterministic budget of capabilities/resources. Example: a build TaskLease may run approved toolchains in one worktree with network disabled and bounded CPU/RAM/output. Requesting network or an external write crosses a capability boundary and is separately authorized.

## 8. Reversible-first execution

Prefer patch transactions, worktrees, temp outputs and atomic replace. Irreversible operations are separate action classes with stronger policy/approval.

## 9. Minimal context protocol

Return structured summaries, changed-file lists, diagnostics and handles before raw bulk output. The AI pulls exact pages/ranges only when needed. This reduces bridge RAM, browser/context pressure and the attack surface of unnecessary untrusted text.

Summaries generated by the bridge must be deterministic extraction/aggregation unless explicitly marked model-generated.

## 10. Security telemetry without prompt retention

Audit action metadata: action type, canonical target class, decision, policy rule, hashes, resource usage, result and timestamps. Do not retain prompts/full source/logs by default.

## Prototype questions

Measure one daemon with isolated SessionContexts first. Only move to worker-per-session if fault/isolation testing proves the extra process boundary is worth its RAM/complexity.
